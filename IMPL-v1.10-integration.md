## How it works

`core/routing.py` is the one file every v1.10 functional converges on (per SPEC-v1.10.md §11's own design), so this pass's job was wiring — not new logic. The unparsed-state machine (shared surface) + `clarify.py` (M1) + `reply_attribution.py`/`discoverability.py` (M2) + the `pause.*_safe` helpers (M3) were all already built and independently Vera-PASSED; this pass makes `handle_inbound_message`/`reparse_pending_unparsed`/`on_callback` actually call into them, in the exact places SPEC-v1.10.md §4/§11 specify (reply-attribution strictly after backfill and before preparse; the live-clarify branch only where the pre-1.10 code already special-cased "no known habit"; the outage message only inside the pre-existing Ollama-DOWN deferral branch). The two Archi-sanctioned consolidations (`core/confirmation.py:send_recovered_confirmation` replacing two independent byte-identical mirrors; the outage-message render-budget cap) were folded into this same pass since they touch the exact code this seam was already rewriting. The biggest real risk — and the actual work beyond wiring — was that several of these newly-wired *defaults* (clarify offers on by default, outage-honesty on by default, the `/log` keyboard now attached to the generic clarifying question, and the zombie row no longer staying `unparsed` forever) changed the observable output of code paths dozens of pre-existing tests already exercised with `Config()` defaults; finding and fixing every one of those was most of this pass's actual effort (see "Iteration log").

## Iteration log

No Vera round yet — this is the initial integration pass. Three rounds of self-caught regressions, found via full-suite reruns after each batch of `routing.py`/`app.py` edits (not a Vera report):

1. **Failure (12 tests, first full-suite run: 4835 passed / 12 failed)**: `tests/test_commands.py::test_normal_message_while_llm_down_is_still_deferred_not_intercepted`, `tests/test_fallback.py::test_below_threshold_confidence_yields_clarifying_question_and_no_row`/`test_custom_threshold_from_config_is_honored`/`test_handler_path_survives_total_llm_outage_no_exception_escapes`, `tests/test_resilience.py::test_deferred_message_acks_writes_unparsed_row_and_never_calls_llm`/`test_reparse_on_recovery_reclassifies_confirms_and_reincludes_in_aggregations`/`test_reparse_leaves_genuinely_unparseable_row_as_unparsed`, `tests/test_v11_integration.py::test_ac4_clarifying_question_carries_no_button`/`test_ac4_deferred_ack_carries_no_button`/`test_ac33_ollama_down_skips_nl_step_entirely_and_defers_as_unparsed_log`, `tests/test_v15_integration.py::test_ac16_ambiguous_text_still_defers_while_ollama_is_down`, `tests/test_v18_release_gate.py::test_typed_log_defers_while_ollama_is_down_but_quicklog_tap_in_the_same_run_still_works`.
   **Root cause**: three independent, all-spec-mandated default-behavior changes this pass wires in for the first time, each invalidating a `Config()`-default assumption several pre-existing tests baked in: (a) `outage.honest_reply=true` (R15) replaces `deferred_ack` with `outage_honest_reply` by default; (b) `clarify.enabled=true` (R6) offers tap-to-fix buttons for any text containing an exact habit-label token — several tests used the fixture text "drank some water", which now guesses `water`; (c) R10's "never silence" now attaches the `/log` keyboard to the generic clarifying question AND to the outage message, which two tests were specifically titled/asserting "carries no button" against (the pre-1.10 behavior R10/R15 deliberately change); (d) `test_reparse_leaves_genuinely_unparseable_row_as_unparsed`'s own premise (a row stays `unparsed` forever) is the literal bug R1/R2 exist to fix.
   **Fix**: (a)/(b) tests whose OWN point is unrelated to the new feature got an explicit `Config.model_validate({"outage": {"honest_reply": False}})` or `{"clarify": {"enabled": False}}` override, preserving their original assertion byte-for-byte; (c) the two "carries no button" tests were updated to assert the new, correct behavior (a real, non-empty `/log`/`clarify:` keyboard) since that's precisely what R10/R15 change on purpose; (d) rewritten to assert the new terminal-closure behavior (`pending_unparsed() == []`, `unparsed_state == "closed"`, one closure send) instead of the old zombie-forever one, with a docstring explaining why.
2. **Failure (2 tests, second full-suite run: 4845 passed / 2 failed)**: `tests/test_discoverability.py::test_command_menu_registers_exactly_the_expected_commands_no_extras`, `tests/test_v12_integration.py::test_command_menu_public_set_excludes_the_four_admin_only_commands` — both assert an exact `set(names) == {...}` command-menu set that doesn't include `"guide"`.
   **Root cause**: adding `/guide` to `core/app.py`'s public menu (R17) is a genuine, spec-mandated set change these two exact-set assertions don't yet know about — missed in the first sweep because the earlier batch of 5 files (which check counts/ordered tails, not exact sets) were the ones caught by the FIRST full-suite run (before `core/app.py`'s own menu edit had even landed yet in that run).
   **Fix**: added `"guide"` to both expected sets, with a comment citing R17.
3. **Self-caught (not a full-suite failure — bugs in `tests/test_v110_integration.py` itself, my own new file, caught immediately on first run: 9/16 failed)**: (a) `text, buttons = channel.actionable[-1]` unpacked a 3-tuple `(chat_id, text, buttons)` as 2 — a copy-paste-from-memory bug in 7 places, not a production issue; (b) `test_ac18_release_1_10_0_announced_once_per_user` assumed English by default, but `announce_release` resolves via `i18n.resolve_unprompted_language`, which defaults to Thai (unlike a reply's `resolve_reply_language`) — fixed by forcing `{"i18n": {"language": "en"}}`; (c) the two-user isolation test's recovery-sweep assertion counted ALL actionable sends to each chat, but an earlier step in the SAME test (the unmapped-reply-falls-through scenario) also deferred a "500" for OTHER with the default `outage.honest_reply=true`, adding an extra send — fixed by asserting on the specific `clarify:<row>:...` callback_data present/absent per chat instead of a raw count, which is also a more direct proof of the isolation claim.
