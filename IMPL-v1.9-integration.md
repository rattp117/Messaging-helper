## How it works

`main.py:handle_inbound_message` now routes `cadence`/`pause`/`resume` to their `execute_*` functions (state changes, followed by `dashboard.refresh`) and `wrapped` to `execute_wrapped` (image-or-fallback, mirrors `/heatmap`). Every milestone/record celebration now asks `streaks.streak_unit(db, habit, user_id)` which wording to use, and — only when a celebration actually fired — appends `wrapped.celebration_burst(config, lang)`. `core/quicklog.py`'s own independent confirmation-building mirror got the identical treatment so the tap-path and typed-path never diverge.

Pause gating follows one pattern at all five R15 sites: each site's own per-habit loop (`send_reminder`'s single habit, `build_checkin_message`/`build_nudge_message`/`compute_daily_summary`/`compute_weekly_stats`'s own `for habit in registry` loops) now skips a habit that `pause.is_paused(...)` currently covers, so a habit-scoped pause suppresses only that habit's own line/reminder — other habits still get their proactive content, and a fully-paused registry degrades naturally to "nothing to report" via each site's own existing empty-result handling. `core/pause.py` gained one new pure read helper, `paused_until`, so the dashboard/`/habits` marker can show the actual end date, not just a bool.

The nightly `grace_tick` (00:05) fans out over `db.active_user_ids()`, calls `grace.evaluate_grace`, and — per Archi's explicit ruling — sends the resulting kind message with `disable_notification=True` unconditionally and with no DND check at all (it reports an already-made, harmless decision). The optional `wrapped_auto` job (month-end, `[wrapped] auto_send`, default `false`) sends a silent card per active user, skipping anyone fully paused or currently in DND; `Channel.send_image` and `execute_wrapped` both gained an additive, defaulted `disable_notification` param to make this possible without changing any pre-v1.9 call site's shape.

Renderer wiring: a cadence habit's `/habits`/dashboard row is entirely replaced by `cadence.cadence_status_line` (already-built by module `cadence`) plus a new weekly-streak suffix; a non-cadence habit's row is byte-identical to v1.8.1. `grace.grace_status_line` is appended to a non-cadence habit's `/habits` line. `records.py`/`streaks.py`/`review.py` each gained a `unit` ("day"/"week") that a caller resolves once via `streak_unit` and threads through to select the pre-existing template (unchanged) or its new `_weeks` sibling — never both at once, and the `_weeks` branch is only ever reached when a cadence row actually exists.

## Known limitations

- **Reminder/check-in/nudge-tick pause suppression is proven by calling the real production functions directly with an injected clock**, not by driving them through the actual `CronTrigger`-scheduled closures in `async_main`. Those three ticks (unlike `weekly_review`/`daily_summary`/`grace_tick`/`wrapped_auto`) read real wall-clock time internally with no injectable override — an established, deliberate codebase convention (see `tests/test_dnd_matrix.py`'s own documented rationale) that keeps production correct but makes driving them through the scheduler in a test nondeterministic. Calling `reminders.run_due_reminders`/`checkins.build_checkin_message`/`nudge.build_nudge_message` directly (the exact functions the scheduler calls, with a controlled `clock=`) is the same technique this codebase's own Veras already use elsewhere, and is not a gap in wiring coverage — the wiring itself (the `pause.is_paused` call inside each production function) is exercised for real.
- **Weekly-review's embedded trends block is filtered via a constructed `HabitRegistry`, not by editing `core/trends.py`.** `trends.py` is shared with the on-demand `/trends` command, which must keep showing every habit regardless of pause (Rule 10: "pause mutes proactive sends only; the user can always query on demand") — filtering at the call site inside `run_weekly_review` keeps that module untouched and correct for both callers.
- **`cadence_weekly_streak_suffix` always says "week(s)"/`สัปดาห์` without singular/plural grammar branching** (mirrors this codebase's own pre-existing "(s)" convention, e.g. `stats_stretch_summary`'s "sessions"/`daily_summary_duration_nogoal`'s "session(s)") — a minor, consistent-with-precedent simplification, not a new pattern.
- **`test_ac30_help_text_mentions_all_four_new_commands_and_grace`** is a light substring check (command tokens present in both languages), not a full-text pin — deliberately loose since `build_help_text`'s exact wording isn't itself an acceptance criterion, only that the four commands are discoverable (AC30's own wording).
- No pushback on any of the four modules' own deliverables — `cadence.cadence_status_line`/`weekly_progress`, `grace.grace_status_line`/`evaluate_grace`/`format_grace_message`, `pause.is_paused`, and `wrapped.execute_wrapped`/`celebration_burst` all composed cleanly into the renderers/main.py with no structural surprises, exactly as each module's own IMPL.md anticipated ("wiring is the later integration pass's job").
