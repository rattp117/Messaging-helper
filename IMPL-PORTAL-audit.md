## How it works

Both handlers resolve the owner's language via `user_prefs.stored_language_pref` + `i18n.resolve_unprompted_language` (fail-open, mirrors `server.py:_owner_language`'s own shape), then wrap their DB read in a try/except: a read failure renders `<h1>{heading}</h1>` + the shared `portal_panel_unavailable` message (pager/table suppressed), an empty result renders the page's own localized empty state (pager suppressed), and a successful read renders a `.collapse` table + (`/audit` only) a `.pager`. Row content reuses `core/audit_view.py`'s existing formatters instead of duplicating them: `_actor_display` (you/display_name/chat_id) for both pages' actor column, `_action_label`/`_ACTION_LABEL_MSG_IDS` for Audit's localized action, `_detail` for Audit's entity + old→new (the exact field set AC23 requires), and `_format_ts` for both pages' timestamp — all private names, imported directly (no import-cycle risk: `audit_view.py` only imports `i18n`/`render_budget`). `/activity`'s Value column formats `value_num` with a unit looked up via a locally-built `HabitRegistry.from_config(deps.config)` (no `PortalDeps` change needed), or renders an em-dash for `habit_type == "text"` rows — the actual privacy boundary is `db.recent_logs_metadata`'s own SQL (never selects `raw_message`, NULLs `value_text` for text-habit rows), so this module has no column to leak from even if it tried.

## Known limitations

- **Interpreted gap, flagged for Vera/Iris/Archi to confirm:** UI.md §3.21 explicitly states only "on page 1 the Newer control is not rendered at all," without saying the same for the last page's Older control. This module applies Maya's stated *general* rule ("a control whose only possible outcome is failure is not rendered", UX.md §5) **symmetrically** — the last page also omits Older. Tested (`test_audit_last_page_older_control_is_suppressed_symmetrically`) and documented inline in `_render_pager`'s own docstring. If Iris intended page 1 to be a special case only, this needs a one-line revert.
- **Activity "Value" unit lookup uses `HabitRegistry.from_config(deps.config)`, not `HabitRegistry.for_user(...)`.** `recent_logs_metadata` returns rows across *all* users, and a row's `category` could in principle be a per-user custom habit (SPEC-v1.7.md) not in `config.habits`. Resolving that correctly would need a per-row `HabitRegistry.for_user(config, db, row["user_id"])` — a DB query per row, which this pass judged not worth the cost for a display-only unit suffix that isn't in AC24's own wording ("category, value" — not "category, value, unit"). A custom-habit row simply renders its bare number, no unit, which is still fully correct and safe, just less pretty than the wireframe's "500 ml" for that edge case. Flagging as a deliberate, low-risk simplification rather than a gap.
- **`PortalDeps.scheduler`/`.channel`/`.stats`/`.ring` are unused by this module** — AUDIT only ever reads `deps.db`, `deps.config`, `deps.owner_id`. No change needed to the shared `PortalDeps` shape.
- **Shared-surface vocabulary gap found during implementation, NOT fixed here (out of this module's file ownership):** the dispatch note stated "the shared surface added the vocab" for `source="portal"` — verification shows this is **not actually true**. `core/audit.py`'s `Source`/`SOURCES` closed vocabulary is still `Literal["command", "nl", "button", "admin", "system"]` (no `"portal"`), even though `core/access.py:approve_user`/`block_user` are already called with `source="portal"` (R-USERACT-1, tested in `tests/test_access.py`). This does **not** block AUDIT's own ACs or tests — `source` renders verbatim/unlocalized regardless of the Python `Literal`'s contents (SQLite doesn't enforce it, and `audit.py`'s own comment already documents "source... is likewise shown verbatim"), and `test_audit_row_source_portal_renders_with_its_own_tag` proves the render path works correctly today. But it is a real, testable gap in the documented closed vocabulary (`tests/test_audit.py::test_...` asserts `set(audit.SOURCES) == {"command", "nl", "button", "admin", "system"}` — no `"portal"`) that belongs to whoever owns `core/audit.py` (the shared surface), not to a single page module. **Recommend**: Archi routes a one-line `SOURCES`/`Source` addition (+ the matching `tests/test_audit.py` update) back to the shared-surface owner or takes it directly — trivial, non-blocking, but should not ship un-flagged.
- **Cross-track test interference, not this module's fault:** the full LINE-only gate currently shows 2 failures, both caused by `src/habit_assistant/core/portal/quota.py` (a parallel Luna's file, landing concurrently in this same worktree) adding a new `channel.send(..., disable_notification=...)` call site that a repo-wide hardcoded-count regression guard (`tests/test_riders.py`, `tests/test_refactor_s2_verify.py`) doesn't yet expect. Verified this module (`audit.py`) makes zero `channel.send` calls and does not appear in the failing assertion's diff at all. Not fixed here (outside AUDIT's file ownership); flagging for Archi/the QUOTA track/integration Vera.
