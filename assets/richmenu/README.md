# Rich menu image — deployment asset

`richmenu.png` is the tappable command-menu image `LineChannel.
register_rich_menu()` uploads at startup (`channels/line.py`, Module A;
`config.toml`'s `[line].rich_menu_image`, default
`assets/richmenu/richmenu.png`). LINE's rich menu is a single flat image
plus a list of pixel-rect tap areas defined in the `POST /v2/bot/richmenu`
call — the PNG here is the **visual** half of that; the areas and the
actions they send are code (Module A).

## Status: final design (v1) — replaces the SPEC-LINE.md §9 OQ3 placeholder

OQ3 shipped a plain grey-and-blue placeholder ("*ship a plain 6-button

## Design tokens

**Style:** Modern & Clean — near-white page, white cards, hairline borders,
one accent, flat. No gradients, no shadows, no emoji.

### Colour

| Token | Value | Use | Contrast |
|---|---|---|---|
| `BG` | `#FAFAFB` | Page background | — |
| `CARD` | `#FFFFFF` | Cell surface | 1.04:1 on `BG` |
| `BORDER` | `#E3E7EC` | Hairline cell separator | 1.24:1 on `CARD` |
| `INK` | `#16181D` | Thai label | **17.76:1** on `CARD` |
| `ACCENT` | `#0F766E` | Icons, command sublabel | **5.47:1** on `CARD` |
| `ACCENT_MID` | `#63A6A1` | Heatmap icon, mid cell | derived — `tint(ACCENT, 0.35)` |
| `ACCENT_SOFT` | `#D4E6E5` | Heatmap icon, coldest cell | derived — `tint(ACCENT, 0.82)` |
| `NEEDLE_SOUTH` | `#3F918B` | Compass icon, south half | derived — `tint(ACCENT, 0.22)` |

One accent only. A deep teal reads calm and clinical rather than shouty,
which suits a health/habit product, and at `#0F766E` it clears **4.5:1 AA
for text** on white — a lighter teal (e.g. `#0D9488`) would not, and this
accent is used for real text, not just decoration. The three tints are
computed from `ACCENT` by `_tint()`, never hand-picked, so the palette
stays a single hue by construction. `generate_richmenu.py` re-checks every
pair above on each run and refuses to write the PNG if one drops below its
floor (4.5:1 text, 3:1 graphics).

### Type

All text — Thai *and* Latin — is set in the repo's bundled
`assets/fonts/NotoSansThai-Regular.ttf` (the same face `core/fonts.py` uses
for chart PNGs, ROADMAP v1.9.0). It covers both scripts, so the image needs
exactly one font file and renders identically on any machine. A system
default font renders Thai as tofu boxes — the exact issue that font was
vendored to fix. **Do not swap it for a system font.**

| Token | Value | Rendered on a phone* |
|---|---|---|
| `LABEL_SIZE` | 78 px | ~12 pt |
| `CMD_SIZE` | 54 px | ~8.4 pt |
| `CMD_BOLDEN` | 1.2 px text stroke | faux-bold (the face has no bold cut) |

\* LINE renders the full 2500 px width at roughly a phone width (~390 pt),
i.e. **~0.156×**. Every size in this asset is chosen against that number,
not against how it looks at full resolution.

### Geometry (8 pt grid)

| Token | Value | Note |
|---|---|---|
| Canvas | 2500 × 1686 | LINE "large"; matches `_default_rich_menu_payload()` |
| Grid | 3 × 2, cells 833 × 843 | `w // 3` × `h // 2`, exactly as the code cuts them |
| `CARD_INSET` | 32 px | → a 64 px gutter between neighbouring cards |
| `CARD_RADIUS` | 32 px | |
| `CARD_BORDER` | 6 px | ~0.9 pt rendered: a true hairline that still survives |
| `ICON_R` | 100 px | every icon is a 200 × 200 box |
| `STROKE` | 18 px | one stroke weight across all six icons (~2.8 pt) |
| `ICON_CY` / `LABEL_BASELINE` / `CMD_BASELINE` | 310 / 546 / 636 px from cell top | fixed baselines, so all three cells in a row align |
| `SS` | 2 | whole canvas drawn at 2× and LANCZOS-downsampled (PIL has no antialiased primitives) |

## The six cells

Left-to-right, top-to-bottom — the order `_default_rich_menu_payload()`
builds its areas in. **Each cell's sublabel is the literal text that tapping
that area sends**, so the artwork can't drift from what the button does.
Tapping delivers it as an ordinary inbound text message that routes through
the existing command dispatch unchanged (R-A10).

| Cell | Tap area (x, y, w, h) | Command sent | Thai label | Icon |
|---|---|---|---|---|
| 1 | 0, 0, 833, 843 | `/log` | บันทึก | solid disc + plus |
| 2 | 833, 0, 833, 843 | `/habits` | ความคืบหน้า | checklist, top item done |
| 3 | 1666, 0, 833, 843 | `/heatmap` | ปฏิทิน | 4×4 heat grid |
| 4 | 0, 843, 833, 843 | `/wrapped` | สรุปภาพรวม | rising bar chart |
| 5 | 833, 843, 833, 843 | `/help` | ช่วยเหลือ | circled question mark |
| 6 | 1666, 843, 833, 843 | `/guide` | เริ่มต้นใช้งาน | compass |

Notes on the labels:

- **บันทึก** and **ปฏิทิน** are the app's *own* Thai aliases for `/log` and
  `/heatmap` (`core/i18n.py`, `help_log_cmd` / `help_heatmap_cmd`) — so the
  menu teaches vocabulary that also works when typed.
- **ความคืบหน้า** matches `/habits`' own gloss in `guide_key_commands`
  ("today's progress"), and **เริ่มต้นใช้งาน** matches `guide_header`.
- Thai is primary and Latin secondary, but both stay visible on every cell —
  bilingual labelling is this edition's whole reason for existing
  (SPEC-LINE.md header).
- `/log` is the only **solid** icon. It's the action people open the menu
  for, so it gets the CTA treatment; it also stops it sharing a plain-ring
  silhouette with `/help` at thumbnail size.

## Accessibility

- Label contrast is **17.76:1** and sublabel **5.47:1** — both well past AA
  (4.5:1). Icons are 5.47:1, past the 3:1 floor for graphics (WCAG 1.4.11).
- **No icon is the sole carrier of meaning** — every cell is labelled in
  words, in two scripts. The heatmap icon's pale tints are texture only; the
  icon's silhouette is carried by its full-strength cells.
- Tap targets are 833 × 843 px ≈ 130 × 132 pt — far past the 44 pt minimum.
- No emoji glyphs anywhere in the image: they render inconsistently across
  platforms and would make the output depend on a colour-emoji font being
  installed wherever the generator runs.

## Regenerating it

```bash
python assets/richmenu/generate_richmenu.py          # writes richmenu.png here
python assets/richmenu/generate_richmenu.py -o /tmp/preview.png
```

Pillow is the only dependency (already present transitively via
`matplotlib`/`[charts]`; otherwise `pip install pillow`). The script is
deterministic — same source, byte-identical PNG — so a regeneration with no
edits produces no diff. Output is a **truecolour** PNG of about **170 KB**,
against LINE's 1 MB ceiling. Quantising this flat art to a 64-colour palette
would cut it to ~60 KB, but at 17% of the budget that saving buys nothing
and costs two things worth more: an indexed PNG is a needless edge case for
a third-party uploader, and a small palette risks banding on the antialiased
icon curves.

Before it draws anything the script **imports the real
`_default_rich_menu_payload()` and asserts its own grid still matches** —
canvas size, cell count, every bound, and every cell's command text. Re-cut
the tap areas in `channels/line.py` and the next run fails loudly instead of
shipping artwork whose buttons point at the wrong commands. It then
re-verifies the contrast table above and refuses to write on a failure.

To change a label, an icon, or the palette, edit the constants at the top of
the script and re-run — everything is a named token, there are no magic
numbers in the drawing code.

## Constraints for any future redesign

- PNG, ≤ 1 MB (LINE's limit), 2500 × 1686 or 2500 × 843 (the compact
  half-height layout — not used here). `tests/test_deploy_line.py` asserts
  the dimensions and the size ceiling.
- ≤ 20 tappable areas (LINE's cap) — 6 leaves plenty of headroom.
- Each area's action is a **message action** whose text is one of this bot's
  own commands (see `core/commands.py` for the full list) — not a postback
  or URI action. A different button set therefore needs **no** Module A code
  change beyond the area-rect ↔ command-text table in
  `_default_rich_menu_payload()`; change it there and regenerate the PNG so
  the two stay in step.
- Keep the filename and pixel size so `config.toml`'s `rich_menu_image` path
  and LINE's own size validation don't need to change.
- The generator has no Raqm/libraqm dependency, so Pillow falls back to
  BASIC text layout. The six labels above are verified to shape correctly
  under it; a **new** Thai label with unusual stacked vowel+tone sequences
  should be eyeballed at full resolution before it ships.
