## Adversarial-angle results (per the coordinator's brief)

1. **Thai alias `ปฏิทิน` full adversarial corpus + collision sweep** — PASS. Extended corpus (13 new phrases: `"ปฏิทิน ปีหน้า"`, glued variants, mid-sentence non-anchored uses, mai-yamok, sentence-final particles, trigger-not-at-start, glued slash form) never misclassifies as heatmap. Collision sweep: 25 parametrized cases covering **every other command's** canonical trigger (undo/history/audit/lang/quiet/checkin/dnd/dashboard/records/trends/help/habits, EN+TH where applicable) confirm direction 1 (none shadow into `heatmap`); 6 cases confirm direction 2 (`ปฏิทิน`'s own shapes are never shadowed by an earlier-checked matcher in `dispatch`'s fixed order). One test-authoring correction made along the way: `/dnd`/`งดรบกวน` resolve to `Command(kind="quiet", ...)` by design (R-D5, a pure `/quiet` alias) — the gap test's expected kind was fixed to match; this is documented, intentional behavior in `commands.py:_match_dnd`, not a defect.
2. **Intensity math** — PASS on every sub-angle: DB target override respected and composes correctly with clamping even when the override is *below* the logged total (`test_day_intensity_override_and_clamp_combined`); multi-entry sum-then-clamp (`test_day_intensity_multiple_entries_sum_and_clamp`); undone-entries-only day → 0 for both a goal-bearing habit (multiple soft-deleted rows, `COALESCE`-guarded) and a boolean habit; boolean and **goal-bearing duration** (the original suite only had goal-*less* duration) both verified; goal-less any-entry rendering already covered by the original suite. Day boundaries: original suite's 23:59:59/00:00:00 naive-string test is real but doesn't exercise actual timezone math — closed with `test_today_in_timezone_converts_aware_utc_clock_to_bangkok_local_date` / its mirror (16:59 UTC still previous Bangkok day) / `test_render_grid_last_cell_follows_real_bangkok_conversion_across_midnight`, all against real `zoneinfo` Asia/Bangkok conversion with an **aware UTC clock**, not just naive local strings. Weeks-param boundaries (1/default/cap/garbage) were already thoroughly parametrized by the original suite (`test_effective_weeks_default_and_cap`); gap file adds garbage at the **dispatch/tail-grammar** layer (`"abc"`, `"-5"`, `"8.5"`, extra trailing tokens) and confirms `/heatmap -5` degrades to a friendly invalid-habit reply rather than being silently misinterpreted as a weeks count.
3. **PNG robustness** — PASS. Byte-identity across languages now proven with a **full** dataset (every cell in a 3-habit/3-type/3-week grid populated), not just one sparse entry. `weeks=52` (the documented cap) produces a valid, sanely-sized PNG (1KB–5MB bounds, no timeout). A user with **zero logs ever** still gets a real, valid all-empty PNG (`render()` and `execute_heatmap()` both verified) — SPEC-v1.6.md §8 doesn't carve out a distinct "no logs" text state for `/heatmap` (unlike `heatmap_no_habits`, which fires only when the *registry* is empty), so an honest blank calendar (GitHub-contribution-graph-style) is the spec-conformant behavior, not a gap. A habit filter for a configured-but-never-logged habit renders correctly (not misrouted to the invalid-habit path). Simulated missing matplotlib was extended from an attribute-monkeypatch (original suite, `th` only) to a **genuine `sys.modules`-hidden ImportError + module reload**, driven through the real `execute_heatmap`, in **both** languages — never crashes, correct fallback text either way.
4. **Documented fixed-7-day-block simplification** — **CONFORMANT with note**, not a FAIL. SPEC-v1.6.md §3.2 ("A calendar grid, one cell per day over N weeks") and R-H1 specify neither a Monday-aligned week nor any particular grid-column start day; nothing in §8's AC-H1–AC-H4 text requires calendar-week alignment either. The module docstring and `IMPL-v1.6-heatmap.md`'s "Known limitations" section both flag this transparently as "not spec-mandated, a deliberate choice" (avoids a future-day masking case). Verified this reading is correct by re-reading §2.1, §3.2, §4 Feature 2, and §8 AC-H1–AC-H4 in full — no rule text anywhere mandates weekday alignment. No spec gap to escalate.
5. **Return contract (`execute_heatmap`'s `"" `/non-empty` split, and the `send_image`-raises edge)** — PASS, including the previously-untested **nested** failure: image render/send fails *and* the text-fallback builder itself raises → still returns the bare `heatmap_fallback_header` string, never `""`, never an exception (`test_execute_heatmap_never_raises_when_both_send_image_and_fallback_text_fail`).
6. **Isolation, zero-LLM proof, render-budget non-issue** — all PASS. Isolation reconfirmed at the `render()` level (not just `execute_heatmap()`). Zero-LLM proof unchanged from the original suite (signature + source-scan checks).
