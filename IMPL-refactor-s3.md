## How it works

`commands.dispatch(text, registry)` strips the text, then walks `_MATCHERS` — a `list[_MatcherEntry]` where each row's `match(stripped, registry) -> Command | None` recognizes one command kind. An ordinary row's `None` means "doesn't recognize this text, keep walking" (every matcher here is documented disjoint-trigger, i.e. pure fall-through); `edit` is the sole exception via its `triggered` predicate — once `_EDIT_TRIGGER` matches the text's shape, that row **commits**: `dispatch` returns `edit`'s own resolution immediately, whether that's a real `Command` or a terminal `None` (a garbled tail), without offering the text to snooze/target/.../query. Three small adapters (`_ignore_registry`, `_bool_matcher`, plus `_resolve_snooze`/`_resolve_edit`) normalize the pre-existing `_match_*` functions' differing signatures (some `bool`, some `tuple`, some registry-less) onto the one uniform row shape — no `_match_*` function's own regex or matching logic was touched, only how `dispatch` calls them and in what order it tries them (same order as before). `_assert_dispatch_invariants(_MATCHERS)` runs once at import time, asserting `query` is the last row, `cadence` precedes `query`, and `edit` is the only row with `triggered` set — so a future edit to `_MATCHERS` that silently reorders or duplicates a row raises `AssertionError` the moment the module is imported, not just when a test happens to catch it.

The 5 EASY clusters each converge on the home module SPEC-REFACTOR.md §6/the dispatch instructions name: the 4 remaining `_user_language_pref` copies → `core/user_prefs.stored_language_pref` (already canonical since v1.8.0; Stage 3 just finishes the job); the 8 `_today*` + 3 `_now_hhmm` sites → new `core/timeutil.py`; the 4 `week_days`/`_week_days` sites → the same `core/timeutil.py`; the 7 Thai-alias pattern builders in `commands.py` → a new shared `_registry_th_tokens(registry)` helper that does only the token-collection-and-escape step, leaving every builder's own trigger literal(s) and regex group shape untouched. `ordinal`/`_ordinal` (the 6th name on rule 12(c)'s list) needed no Stage 3 work at all — Stage 2 (v1.9.2) already consolidated it into `core/confirmation.py`; a new test (`test_ordinal_has_exactly_one_definition_across_the_whole_src_tree`) locks that fact in.

## Known limitations

- `heatmap.py:_today_in_timezone` is not a full deletion — it's a 1-line delegating wrapper, kept solely because `tests/test_heatmap_gaps.py` calls it directly by name and editing that test is outside this stage's sanctioned scope. This is not a residual duplicate (the actual logic/body lives only in `timeutil.py` now) and mirrors an already-accepted codebase precedent (`reminders.py:_user_language_pref`).
- `reminders.py:_today_str(config)` (no injectable clock, always real `datetime.now`) was deliberately left unconsolidated — it has a genuinely different signature/contract from the 8 `timeutil.today_in_timezone`-shaped sites and SPEC-REFACTOR.md's own rule 12(b) lists only 8 sites, not 9.
- No production code outside `core/commands.py` and the 13 dedup-consumer files was touched; `core/routing.py`'s handler-arm scaffold (rule 10) and the `db.py` god-object/dead-code/test-health items (Stage 4) are untouched, per scope.
