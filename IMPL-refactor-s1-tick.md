## How it works

`core/reminders.py:run_due_reminders` now fetches its per-tick reminder-time overrides once (`_bulk_reminder_time_overrides`, consuming `storage/db.py:Database.all_reminder_times()`) instead of once per (user, habit), and only resolves a user's language when a reminder for them is actually about to fire. `core/checkins.py`/`core/nudge.py`'s message builders fetch `db.active_pauses(user_id)` once per call and reuse it across every habit via a same-file mirror of `pause.is_paused`'s coverage check, rather than re-querying per habit. `main.py` merges the three independent minutely cron jobs into one (`minutely_tick`) that reads the active-user fan-out set once and passes it to all three tick functions, each of which now accepts that list instead of re-deriving it — falling back to its own `db.active_user_ids()` call when nothing is supplied, so every pre-existing direct caller/test is unaffected. Each of the three tick calls inside `_minutely_tick` is independently wrapped in `try/except Exception` (logged, then continue) so one tick function raising can never suppress the other two for that same minute — restoring the isolation the old three-independent-scheduler-jobs design had.

## Known limitations

- **`pause.py` duplication, not a shared extraction.** Stage 1's file ownership excludes `core/pause.py` from this track (not in SPEC-REFACTOR.md §6's Stage 1 file list). The active-pauses-reuse remedy (rule 7) is therefore implemented as a same-file `_is_paused_in` helper in both `checkins.py` and `nudge.py`, each mirroring `pause.is_paused`'s exact coverage-check logic rather than changing that function's signature. This is a small, deliberate, documented duplication (mirrors this codebase's own established pattern for exactly this kind of cross-file-ownership constraint, e.g. `quicklog.py`'s mirror of `main.py`'s confirmation branches, rule 11) — a future Stage could extract a shared `pause.is_paused_in(rows, habit_id, when_str)` if `pause.py` is ever brought into scope.
- **`_bulk_reminder_time_overrides`'s call to `db.all_reminder_times()` is not itself wrapped in a try/except**, unlike `_goal_already_met`/`effective_quiet_windows`'s fail-open posture for their own DB reads (Vera's own observation, `TEST-refactor-s1.md` Section C docstring). A DB error there now propagates out of `run_due_reminders` — but per round 2's fix, that no longer suppresses `checkins`/`nudge` for the same minute (each of the three ticks is independently isolated in `main.py:_minutely_tick`); it only means that one particular reminder tick is skipped for that minute, logged, same as any other run_due_reminders-level failure. Not changed in this round since it wasn't the flagged finding and isn't itself a behavior regression vs. pre-Stage-1 `run_due_reminders` (which had no such try/except either) — noted here for Archi/a future round to decide whether it's worth adding.
- The job id `reminder_tick`/`checkin_tick`/`nudge_tick` → `minutely_tick` rename is internal scheduler wiring with no observable effect (no user-visible command, log line, or catalog string references these ids); `tests/test_v19_integration.py`'s shared-harness docstring comment (lines ~88-92) still narrates the pre-consolidation three-job wiring rationale for why its `_FakeScheduler` captures `kwargs` — left as-is (a historical/design note, asserts nothing, out of this track's file scope to edit).

## Iteration log

**Round 1 (initial handoff):** two self-caught issues during my own smoke-testing (not Vera findings): (1) `set_reminder_times` enforces a `UNIQUE(user_id, habit_id, time)` constraint, so an initial test draft that tried to insert a literal duplicate row to exercise `_reminder_times_from_overrides`'s `sorted(set(...))` dedup failed with `IntegrityError` — fixed by testing only the sort behavior (dedup is defensive/unreachable through legitimate storage, same as it always was in `effective_reminder_times`). (2) `test_consolidated_minutely_tick_calls_active_user_ids_once_ac4` initially tried to invoke the captured job function *after* `async_main` returned, but `async_main`'s own `finally` closes `db` immediately after the fake channel's `run()` raises — fixed by invoking the job from inside the fake channel's `run()`, mirroring `tests/test_v19_integration.py:_V19Channel.run`'s established pattern. At handoff, AC1's strict ≤3 floor was blocked on the (not-yet-landed) `Database.all_reminder_times()` accessor — resolved before round 2 when the parallel S1-A/db track added it verbatim to the proposed shape.

**Round 2 (Vera's `TEST-refactor-s1.md`, one genuine finding):**
- **Failure → root cause:** `test_one_ticks_exception_does_not_suppress_the_other_two_ticks_same_minute` (`tests/test_refactor_s1_gaps.py`) failed — Vera proved that the Stage 1 job consolidation silently dropped the pre-Stage-1 per-job failure isolation. Under the old design, `reminder_tick`/`checkin_tick`/`nudge_tick` were three independent APScheduler jobs; one raising never affected the other two (separate executor slots). `_minutely_tick`'s naive sequential `await run_due_reminders(...); await checkins.run_due_checkins(...); await nudge.run_due_nudges(...)` had no try/except between them, so an exception escaping `run_due_reminders` (e.g. a DB error not caught by its own internal fail-open helpers) aborted the whole tick — `checkins`/`nudge` were never called for that minute. This directly contradicted rule 2's own claim ("the three fan-outs are independent and order-free") and this codebase's pervasive per-user/per-habit fail-open convention.
- **Fix:** wrapped each of the three `await`s in `main.py:_minutely_tick` in its own `try/except Exception`, logging via `logger.exception(...)` (matching this file's established style, e.g. `weekly_review_job`'s per-user chart try/except) and falling through to the next tick function. `active_ids = db.active_user_ids()` stays outside all three try blocks (unchanged — a failure there was never isolated per-job even pre-Stage-1, since all three old jobs each called it independently and none guarded that call either).
- **Verification:** exit-bar command `pytest tests/test_refactor_s1_gaps.py tests/test_refactor_stage1_tick.py tests/test_reminders.py tests/test_checkins.py tests/test_nudge.py -q` → **148 passed, 0 failed** (Vera's file untouched). Full suite → **4304 passed, 0 failed, 1 skipped, 1 xfailed (4306 total)**.
