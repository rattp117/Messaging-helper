## How it works

`/history` is a smaller, single-user cousin of `/audit`: same shape-recognize/execute split, same read-only/LLM-free/newest-first/budget-guarded posture, but with the owner concept removed entirely — `db.recent_logs`'s `WHERE user_id = ?` scoping is the only "who can see this" gate there is (no `owner_chat_id` parameter anywhere in `history_view.py`, and `main.py` routes it with no `access.classify` check at all, unlike `/audit`). The one genuinely new piece of machinery is the extraction: `core/audit_view.py`'s v1.3.0 "the 50-row cap alone doesn't bound message length" fix (per-value truncation + a structural total-length guard that drops the oldest rows and appends a footer) is exactly the fix `/history` needs too, so rather than copy-pasting it a second time, it now lives in `core/render_budget.py` with the footer text injected by the caller — `audit_view` passes a closure rendering `audit_more_rows`, `history_view` passes one rendering `history_more_rows`, and neither module needs to know anything about the other's i18n keys. `commands.py`'s new `"history"` kind reuses two fields (`category`, `limit`) that already existed for `/target`/`/audit` rather than adding new ones, and its Thai alias `ย้อนหลัง` was hardened from the outset (registry-anchored habit token + numeric-only tail, full-message `$`-anchored) rather than retrofitted later the way `เตือน`/`ภาษา`/`เงียบ` each needed a second round after shipping permissively — this feature landed after that lesson was already learned twice.

## Known limitations

- **`describe_log` reused verbatim, including its own known limitation** (already documented in `core/undo_ui.py` and re-flagged in SPEC-v1.4.md §9's own "risks" section): for a text habit (diary), the description segment and the quoted `raw_message` segment can show overlapping/near-identical content (a diary entry's "description" IS its snippet). Accepted per the spec's own explicit risk note — not fixed, since the spec calls it out as expected, not a defect.
- **No unit polish beyond what `describe_log` already provides** — this is a non-issue for `/history` specifically (unlike `/audit`'s own flagged limitation), since `describe_log` already renders the unit (`"500 ml water"`) — flagging only that this module inherits whatever `describe_log`'s own per-type formatting produces, good or bad, by design (R-R2's explicit "reuse, don't reimplement" instruction).
- **`DEFAULT_LIMIT`/`MAX_LIMIT` are a second pair of constants**, not imported from `audit_view.py` (both modules independently define `20`/`50`) — R-B1 only asks for the render-BUDGET helpers to be shared (truncation + the length-guard), not these two small ints; treating a values-only coincidence as a real shared contract would have been over-abstraction for two integers with no other relationship between the modules.
- **The Thai alias `ย้อนหลัง`'s trailing-N is Latin-digit-only** (`\d+`, not Thai numerals ๐-๙), consistent with every other numeric-tail command in this codebase (`/target`, `/remind`, `/audit`) — not a gap specific to this feature.
