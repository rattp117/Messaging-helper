## How it works

`core/commands.py:_match_wrapped` recognizes `/wrapped [month]`, alias `/recap [month]` (slash-anchored, fully permissive tail), and two Thai triggers: `สรุปเดือน` ("month recap") always means the calendar-month window regardless of any tail; `การ์ดสรุป` ("recap card") is the generic trigger, defaulting to the last-4-weeks window unless followed by an explicit `เดือน`/`month` tail. Both Thai triggers dispatch bare (no habit token in this grammar — Rule 21 always uses the whole registry). `execute_wrapped` resolves `command.pref_value == "month"` into a `Period` (`"4w"`/`"month"`), computes the window via `_window_days`, and calls `render()`.

`render()`/`_build_figure` assemble ONE matplotlib `Figure`: a title row, one row per habit (a mini goal-fulfillment heatmap strip reusing `heatmap.py:_day_intensity`, next to a text summary — period total via `records.period_total`, best day via the same function called per-day, and a cadence-aware streak line via `streaks.compute_streak`/`streak_unit`), and a "biggest mover" row picking the single largest `|pct_change|` (falling back to `|delta|`) from `trends.compute`. A user with zero logs in the window still gets a real card back — a friendly empty-state message replaces the per-habit rows rather than showing a wall of zeros. `_render_png` just calls `_build_figure` then `savefig`+`close`; the split exists purely so tests can inspect the actual matplotlib `Text` artists. Missing matplotlib, an empty registry, or any render exception makes `render()` return `None` (never raise); `execute_wrapped` then sends a bilingual text fallback that mirrors `heatmap.py`'s R-H2 shape exactly. `celebration_burst(config, lang)` is a standalone zero-asset helper — `""` when `[wrapped] celebrate_burst` is off, else the bundled `"🎉🎊🥳"` string — for `main.py`'s later integration wiring to append to a milestone/record celebration line; it does not touch the card.

## Smoke test done

- Ran a standalone script (`scratchpad/smoke_wrapped.py`) against a scratch on-disk SQLite DB (never `data/habits.db`) seeding 28 days of numeric/boolean/text logs plus a `db.set_cadence` row: rendered a real PNG (`heatmap.render`-equivalent 18–35 KB, correct `\x89PNG\r\n\x1a\n` magic), asserted Thai labels ("น้ำ"/"ยิม") are present as real `ax.texts` `Text` objects (not just somewhere in PNG bytes), confirmed the zero-logs friendly-empty-state string is drawn, exercised the no-matplotlib fallback (`MATPLOTLIB_AVAILABLE=False`), ran `execute_wrapped` end-to-end for both `"4w"`/`"month"` periods and both languages (checked captions), exercised the render-unavailable text-fallback path, and verified `celebration_burst` on/off.
- **Caught and fixed a real layout bug during this smoke test**: the first draft placed each habit's text summary via `ax.text(x=1.03, ...)` (axes-fraction overflow past 1.0) — this is silently clipped at the *figure's* own canvas edge on `savefig`, not just the axes, so the label/total/streak text was completely invisible in the actual saved PNG despite existing as a `Text` object. Fixed by giving each habit row a nested 2-column gridspec (heatmap strip + its own text subplot) so the summary text is genuinely on-canvas. Re-rendered and visually inspected both an English and a Thai card (`Read` tool on the PNG) to confirm the fix — see the module docstring's own note on this for future readers.
- Also fixed, found via the same visual inspection: emoji (🎉/📈/📭) drawn directly into the image showed matplotlib `findfont`/glyph-missing warnings (DejaVu/Noto Sans Thai carry no emoji glyphs) — added `_for_image()` to strip a leading decorative emoji before text is drawn onto the figure (the chat caption/fallback text, which Telegram renders client-side, keeps the emoji). Confirmed the warnings are gone after the fix.

## Known limitations

- **AC28 (month-end auto-send) is intentionally not implemented here** — see above; it is `main.py` integration scope, not `core/wrapped.py`'s file list per SPEC-v1.9.md §6/§11. Nothing in this module blocks it: `render`/`execute_wrapped`/`config.wrapped.auto_send` are all ready to be driven by a scheduler tick.
- **English month name inside Thai cards** (`wrapped_period_month`/`wrapped_caption_month`): mirrors `core/heatmap.py`'s own documented, accepted limitation — this app never calls `locale.setlocale`, so `date.strftime("%B")` is always English regardless of `lang`. The Thai variant wraps the English month name in Thai surrounding text ("เดือน August 2026") rather than pretending to localize the month name itself.
- **Emoji stripped from the image, kept in chat text**: the bundled fonts (DejaVu Sans / Noto Sans Thai) have no emoji glyphs, so a 🎉/📈/📭 drawn directly into the PNG would itself show as a tofu box (unrelated to AC27's Thai-script requirement, but the same visual failure mode) — `_for_image()` strips a leading decorative emoji before text is drawn onto the figure; captions and the text fallback (plain chat strings, rendered by Telegram itself) keep the emoji.
- **"Best day" and "biggest mover" are window-scoped, not lifetime records.** Rule 21 lists "best day" among the card's pieces without specifying window-scoped vs. lifetime-record semantics; I read "reuses `records.period_total`" (not `db.get_record`) as the intended reuse target, so "best day" is the highest single-day total *within the recap window*, computed by calling `period_total` once per day — not the all-time `best_day` record `/records` tracks. If the product intent was the lifetime record instead, that's a one-function swap (`db.get_record(user_id, habit.id, "best_day")`), flagging this judgment call explicitly per the escalation guidance.
- **Streak values are the CURRENT streak as of the window's end date**, computed via `streaks.compute_streak(db, config, habit, today, user_id)` — the same call-site shape `records.py:193`/`dashboard.py:237` use — not a lifetime-longest value. This matches how every other renderer in the app surfaces "streak" (dashboard, daily summary, milestone) and is what "cadence-aware, weeks-met shown" (AC26) naturally describes.
- No pushback on the spec or shared surface — `core/streaks.py:streak_unit`/`compute_streak`, `core/fonts.py:register_thai_font`, and `core/records.py`/`core/trends.py`/`core/heatmap.py`'s existing public (and one private, `_day_intensity`) functions composed cleanly with no structural surprises.
- Did not touch `main.py`, `storage/db.py`, `config.py`, or `storage/migrations.py` — none were needed for this module's scope (read-only, no new storage, `WrappedConfig` already existed).
- `tests/test_cadence.py::test_a_genuinely_missed_week_breaks_the_cadence_streak` failed transiently during one intermediate full-suite run while the parallel `cadence` module was still landing; it was green (along with everything else) in the final full-suite run reported below. Not a `wrapped`-owned file — noted per the "failures outside your files: note and move on" instruction, and it resolved on its own by the final run.
