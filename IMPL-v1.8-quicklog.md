## How it works

`build_keyboard(registry, config, db, lang, user_id)` walks the caller's already-resolved per-user `HabitRegistry` and, per habit, emits either amount buttons (sorted-unique unit-alias multipliers, or a `[¼G, ½G, G]` goal-derived ladder via `targets.effective_goal`, capped to `config.quicklog.max_buttons_per_habit`), a single boolean "done ✓" button, or nothing (text habits, or a numeric/duration habit with neither aliases nor a goal). `handle_log_callback` is the `on_callback` body for a tapped `log:<habit>:<value>` button: it regex-validates the payload shape and numeric bounds, resolves `habit_id` against the tapping user's own `registry` (a foreign/missing habit → friendly no-op; a malformed/out-of-range/non-quick-loggable payload → logged and silently ignored, mirroring `undo_ui`'s discipline), then writes the `LogEntry` and sends the water/stretch/generic confirmation — a line-for-line mirror of `main.py:handle_inbound_message`'s own confirmation branches (proven byte-identical by dedicated tests, the same technique `test_undo_ui.py` already established for this codebase) — including the milestone/record celebration suffixes and the dashboard refresh. `core/reactions.py` is independent: `emoji_for_habit` resolves a habit's id, then its type, then "✅" as the ultimate fallback (AC-A1's own pushups example pins the type fallback for numeric/duration to 💪, matching `stretch`), and `react` wraps `channel.set_message_reaction` in its own fail-open try/except on top of `TelegramChannel`'s already-fail-open transport layer. Neither `quicklog.py` nor `reactions.py` imports an LLM client — text-type habits are excluded from the keyboard and from `handle_log_callback` before the confirmation formatter is ever reached, so R-Q6's "zero-LLM" holds by construction.

## Known limitations

- `main.py` is untouched, per scope — `/log` routing, the `on_callback` `"log:"`-prefix dispatch, and firing `reactions.react` after a successful *typed* log (using `inbound_message_id`) are all the later, sequential integration pass's job. `build_keyboard`/`handle_log_callback`/`react` are written to the exact SPEC-v1.8.md §5 signatures so that pass can drop them in directly.
- `channel.send_actionable`'s existing (pre-v1.8) implementation renders `list[Button]` as a single inline-keyboard row (`channels/telegram.py:build_send_actionable_request`). Since `build_keyboard` can return many buttons (every loggable habit's amount buttons, flattened), a habit-rich registry will render as one long single-row keyboard rather than multiple rows. This is a pre-existing constraint of the shared `send_actionable`/`Button` surface (not owned by this module — a multi-row keyboard would need a `channels/base.py`/`channels/telegram.py` signature change), not a bug introduced here; flagging for Archi in case a follow-up wants multi-row layout.
- The goal-derived ladder's rounding (`_round_ladder_step`: nearest integer, floored at 1) and the "cap keeps the smallest-N amounts" convention (both for alias multipliers and the ladder) are Luna's own reasonable-default judgment calls per SPEC-v1.8.md §9's explicit "the exact roundings are Luna's to pick sanely" note — documented in `core/quicklog.py`'s own docstrings, not asserted as the only valid choice.
- `REACTION_EMOJI`'s type-fallback for numeric/duration habits is 💪 (matching AC-A1's own pushups example, which reuses `stretch`'s built-in emoji) rather than a more granular per-type icon — a deliberate reading of "a small type map for the rest" against the spec's own worked example, documented in `core/reactions.py`.

## Iteration log — round 2 (Vera's `TEST-v1.8-quicklog.md`, 4 defects)

All four fixes confined to `core/quicklog.py`, per the dispatch brief. `tests/test_v18_quicklog_gaps.py` (Vera's file) was not touched — it defines the target and now passes as-is, 37/37.

1. **Language-preference parity (load-bearing, AC-A2/AC-A6)** — `test_handle_log_callback_ignores_the_tapping_users_stored_lang_preference`.
   - *Root cause:* `handle_log_callback` (was line 234) called `i18n.resolve_reply_language(source_text, config)` with no `user_pref` argument, so it could never honor a tapping user's stored `/lang` preference — unlike every other reply path in the codebase (`main.py:_stored_language_pref`, `core/reminders.py:_user_language_pref`, `core/access.py:_resolve_unprompted_language_for`).
   - *Fix:* added `core/quicklog.py:_stored_language_pref(db, user_id)` — a same-file copy mirroring `main.py:_stored_language_pref` exactly (fail-open, defaults to `"auto"` on a missing row or DB read error) — and now call `i18n.resolve_reply_language(source_text, config, user_pref=_stored_language_pref(db, chat_id))` in `handle_log_callback`. A `/lang th` user now gets an identical Thai confirmation from both tap and typing.

2. **Unicode-digit forgery (AC-A3)** — `test_handle_log_callback_rejects_non_ascii_unicode_digits_in_the_value`.
   - *Root cause:* `_LOG_CALLBACK_RE`'s bare `\d` matches any Unicode decimal-digit (category Nd), not just ASCII `0-9` — a forged `log:water:๕๐๐`-style payload (Arabic-Indic/Thai/fullwidth digits) passed the regex and `float()`, producing a real unvalidated write.
   - *Fix:* compiled `_LOG_CALLBACK_RE` with `re.ASCII`. The habit-id group was already a literal `[a-z0-9_]` char class (unaffected); only the value group's `\d` needed the flag.

3. **Negative-goal spurious button** — `test_goal_ladder_negative_goal_produces_no_buttons_not_a_crash`.
   - *Root cause:* `_round_ladder_step` floored ANY non-positive `round(x)` result to `1.0`, conflating "small positive goal rounds to 0" (the case the floor was written for) with "goal itself is negative" (`round(-5/4)=-1` also got floored to `1.0`).
   - *Fix:* the floor-to-1 now only fires when the *input* `x` is positive (rounds down to 0); a non-positive `x` is returned as-is, so `_goal_ladder`'s existing `value > 0` guard filters it out — a negative-goal habit is now skipped entirely (no button), same as a goal-less habit.

4. **Huge-fractional-goal dead button** — `test_build_keyboard_huge_fractional_goal_produces_a_callback_payload_that_still_round_trips`.
   - *Root cause:* `_format_amount` used `f"{value:g}"`, whose 6-significant-digit default switches to scientific notation for a large non-integer (`"1.23457e+08"`), which `_LOG_CALLBACK_RE` cannot match — a dead button.
   - *Fix:* switched to fixed-point (`f"{value:.6f}"`, trailing zeros/point trimmed), matching `_LOG_CALLBACK_RE`'s own value grammar (up to 6 fractional digits) so every rendered amount round-trips.
