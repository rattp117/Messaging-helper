## How it works

`config.py` now carries the LINE branch's whole config surface as inert, fully-defaulted additions: `ChannelConfig.type` defaults to `"telegram"` and `OllamaConfig.enabled` defaults to `True`, so the repo's own `config.toml` (which sets neither) is byte-unchanged — the LINE deployment's `config.toml.line` template (Module D) is the only place that flips them. `Secrets` no longer enforces required fields at the pydantic level (both channels' credentials are optional there); `load_secrets(env_file, *, channel_type="telegram")` does that check explicitly after construction, against whichever field set `channel_type` names, so Integration's own `core/app.py` wiring (R-I1) just needs to pass `channel_type=config.channel.type` at its three existing call sites — untouched today, still validating exactly the Telegram pair. Migration 014 adds `push_ledger` (quota bookkeeping) and `users.digest_opt_out` (opt-out default `0`, matching the locked "digest ON by default" decision) with the same additive, `IF NOT EXISTS`/`ALTER ADD COLUMN` idiom every prior migration uses; the five new `Database` methods are plain upsert/sum/read wrappers mirroring `set_target`/`upsert_record`'s "storage just stores" split. The pytest marker mechanism is two registered marker names in `pyproject.toml` plus per-test/per-module `@pytest.mark.telegram_only` / `pytestmark = pytest.mark.llm_only` applied where a test's own subject matter is unambiguously dead on this branch; `pytest -m "not telegram_only and not llm_only"` is the LINE gate.

## Known limitations

- **The 153 tests marked so far are a first, high-confidence pass, not an exhaustive sweep.** Only tests that unambiguously construct/exercise the *real* `channels.telegram.TelegramChannel` or `llm.ollama_client.OllamaClient` (or classify/extract through them) were marked. Roughly two dozen more files reference one of those two real classes but are genuinely *mixed* — e.g. `tests/test_query.py` covers both `classify_query_intent` (LLM-backed, dead in no-LLM mode) *and* deterministic timeframe/aggregation/formatting logic (must stay in the gate) in the same file; `tests/test_resilience.py` covers Telegram poll backoff, Ollama retry, *and* migration 002 in one file. Deliberately left unmarked rather than guessed at — none of Module B's or Module A's actual behavior changes have landed yet, so I have no way to know today exactly which assertions in those mixed files will become obsolete. **This is Module A's and Module B's own call to make as they touch `channels/line.py`/`core/routing.py` etc. and can see precisely what breaks/goes dead.** At shared-surface completion this is harmless: nothing in core behavior changed, so the full unfiltered suite is still 100% green regardless of what's marked.
- **One pre-existing, unrelated test failure**, confirmed via `git stash` against the untouched worktree baseline (fails identically with none of this pass's changes applied): `tests/test_v110_m3_gaps.py::test_run_due_reminders_actually_paused_user_suppressed_others_unaffected`. Not caused by this pass; out of shared-surface scope. Flagging for Archi/Vera rather than silently fixing a file (`core/reminders.py`/`core/pause.py`) neither the shared surface nor any LINE module owns.
- **Six pre-existing CLI/backup test failures were latent, not fixed by code** — `tests/test_cli.py`/`tests/test_backup.py` spawn the real entry point as a subprocess and need `load_secrets()` to succeed against something; the fresh worktree had no `.env`. Created a local, gitignored `.env` with dummy Telegram values (mirrors `.env.example`) rather than touching any spec-owned file — pure test-environment setup, confirmed pre-existing via the same `git stash` check.
- **No `RELEASE_NOTES["1.0.0-line"]` entry added** — optional, not required by any AC, and the digest's own "release announcement" line (R-C1 item (e)) degrades to nothing until one exists, same as the existing "no entry → no announcement" convention. Left for whoever wires the digest's actual copy (Module C) to decide if/when to add one.
- `channels/line.py`'s stub (`LineChannel.__init__` raising `NotImplementedError`) is untouched, as directed — Module A's own build.
