## How it works

`LineChannel` never talks to the LINE API directly from `send`/`send_actionable`/`send_image` — each builds one or more LINE message-object dicts and hands them to `_emit`, which checks a module-level `contextvars.ContextVar` (`_REPLY_CONTEXT`). `LineWebhookServer`'s single worker task sets that contextvar (via `LineChannel._reply_scope`, a context manager yielding `{"replyToken": ..., "buffer": []}`) before `await`-ing the inbound handler (`on_message`/`on_callback`) and reads the accumulated buffer back out after — so every `channel.send(...)` call the handler makes during that one event gets appended to `ctx["buffer"]` instead of hitting the network, then `LineChannel._flush_reply` sends the whole buffer as **one** `POST /v2/bot/message/reply` call (capped at 5 objects, overflow dropped with a WARN). Outside any active context — only the digest's proactive push — `_emit` calls `_push` instead, which POSTs to `/v2/bot/message/push` and, only on success, calls `db.increment_push(chat_id, yyyymm)`, making the channel the single authoritative point where LINE's push quota is counted. Inbound, `LineWebhookServer._handle_callback` verifies `X-Line-Signature` over the raw request bytes with `hmac.compare_digest` before touching the body at all, then just enqueues each event onto an `asyncio.Queue` and returns `200` — a separate long-running `_worker` task drains that queue one event at a time (FIFO, fully `await`ed before the next), guaranteeing per-user ordering by construction (a single global worker). `GET /media/{token}.png` and the TTL sweep operate on the same `media_dir` that `send_image` writes `secrets.token_urlsafe(16)`-named PNGs into; the token regex (`^[A-Za-z0-9_-]{1,64}$`) makes path traversal structurally impossible rather than relying on path-resolution checks.

## Iteration log

### Round 1 — Vera's adversarial pass (`TEST-LINE-A.md`, `tests/test_line_a_gaps.py`, 49 new tests, 5 failing)

- **Failure 1 — `test_callback_valid_signature_well_formed_json_wrong_top_level_shape_never_500s`** (4 parametrized cases: `[1,2,3]`, `null`, `42`, `"just a string"`).
  - **Root cause:** `channels/line_webhook.py:_handle_callback` did `payload.get("events")` unconditionally after `json.loads` succeeded. `json.loads` succeeding only guarantees valid JSON *syntax* — the top-level value can legally be a list/null/int/str, none of which have `.get`. LINE always sends an object, but nothing enforced that before this line, so a correctly-signed request with a non-object top level raised an unhandled `AttributeError`, which aiohttp turned into a `500` — a third, undocumented outcome against §3.4's own "200 or 400, no other option" contract.
  - **Fix:** added `if not isinstance(payload, dict): return web.Response(status=400)` (with a WARN log) immediately after the JSON parse succeeds, before the `.get("events")` call — treats "valid JSON but not the documented `{"events": [...]}` shape" as the same "unparseable body" 400 bucket as a syntax error, matching Vera's suggested fix and §3.4's exact wording.
- **Failure 2 — `test_callback_valid_signature_invalid_utf8_body_returns_400_not_500`**.
  - **Root cause:** the `try/except` around `json.loads(raw)` only named `json.JSONDecodeError`. `json.loads` on certain invalid-UTF8 byte sequences (e.g. `b"\x80\x81\x82\x83"`) raises `UnicodeDecodeError` during its own internal encoding-detection step *before* it ever gets to JSON syntax parsing — a different exception type, uncaught by that clause, again surfacing as an unhandled `500`. R-A2's own text ("a body that fails JSON parsing → 400") makes no distinction between *why* parsing failed.
  - **Fix:** widened the except clause to `except (json.JSONDecodeError, UnicodeDecodeError):` — both now resolve to the same `400` + WARN log path.
  - Both failures shared one fix location (`_handle_callback`'s parse-and-shape-check block) and were fixed together in one edit, per Vera's own recommendation.
- **Verification:** `test_callback_events_key_not_a_list_does_not_crash_the_worker` (dict-shaped `{"events": "abc"}`, a case Vera explicitly distinguished as already-correct: 200 + worker survives per-char garbage) still passes unchanged — the new `isinstance(payload, dict)` guard is narrower than that case and doesn't touch it.
- **Result:** `pytest tests/test_line_channel.py tests/test_line_webhook.py tests/test_line_a_gaps.py -q` → **109 passed, 0 failed** (24 + 36 + 49). Full Module-A set including the 3 rewritten pre-existing tests: `pytest tests/test_line_channel.py tests/test_line_webhook.py tests/test_line_a_gaps.py tests/test_channels.py tests/test_charts.py tests/test_deliverables.py -q` → **182 passed, 1 skipped** (the skip is Vera's own noted unrelated pre-existing one, `test_channels.py:257`). No test file was edited to reach this — only `src/habit_assistant/channels/line_webhook.py:_handle_callback`.
