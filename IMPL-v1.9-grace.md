## How it works

`evaluate_grace(db, config, registry, user_id, today, clock=datetime.now)` is called once per active user (the nightly fan-out itself — `active_user_ids()` + the 00:05 tick registration — is integration's job in `main.py`, out of this pass's scope; this function's signature is deliberately droppable into that fan-out as-is). For each habit in the registry it skips cadence habits (`db.get_cadence(...) is not None`, R6/AC16) and habits whose yesterday isn't a genuine miss — where "genuine miss" re-derives `classify_day`'s own QUALIFIED/NEUTRAL split for exactly one date via `streaks.day_qualifies` + `db.paused_dates` (a paused yesterday is NEUTRAL, not MISSED, so grace never fires during a pause — no import of `core/pause.py` needed, keeping file ownership disjoint from M3). It then checks `db.grace_protected_dates` (idempotency guard against a same-night re-run) and `db.grace_used_in_week` (R11: one grace per ISO week) before computing `protected_streak = streaks.compute_streak(..., day_before_yesterday, ...)` — a value `< 1` means "no streak to protect" (a brand-new habit's first miss, or any habit with no qualifying history), so nothing is bridged. Otherwise it writes the `grace_ledger` row, a fail-open `audit.record(action="grace_consumed", source="admin", entity=habit.id, new_value=protected_date)` row, and returns `(habit, protected_streak)` in the list the caller uses to build the kind message via `format_grace_message`. Once the ledger row exists, the shared engine's own `classify_day` (built in the shared-surface pass, not touched here) treats that date as NEUTRAL on every subsequent read — this module never mutates `compute_streak`'s own read path, only the ledger it reads.

## Known limitations

- **Nightly-tick scheduler wiring is explicitly out of scope**, per the dispatch — `evaluate_grace`'s signature (`db, config, registry, user_id, today, clock`) is droppable into `main.py`'s 00:05 tick + `active_user_ids()` fan-out as-is; I did not touch `main.py`.
- **`source="admin"` for the `grace_consumed` audit row is a judgment call.** `core/audit.py`'s `Source` literal (`"command" | "nl" | "button" | "admin"`) has no dedicated "system/scheduled job" value; grace is the first purely system-initiated mutation in this codebase's audit history (every prior action is a direct or admin-adjacent user action). I chose `"admin"` as the closest fit, mirroring `core/access.py`'s own precedent of using `"admin"` for a state transition "nobody else acted" to cause. This is easily changed if Archi/Vera disagree.
- **DND/quiet-hours suppression for the grace message is deliberately NOT implemented here**, and I want to flag why rather than silently omit it: SPEC-v1.9.md §5's interface for `evaluate_grace` takes no `channel` and does not send anything — it only writes the ledger/audit and returns what *would* be said; §6 assigns the actual `channel.send` (and any DND gating around it) to `main.py`'s integration step. Unlike pause (R15, which explicitly lists the five proactive-send sites that must check `is_paused` before sending), the spec's Rules 8–11 never mention a DND check for the grace message at all. I did not add one on my own initiative (scope discipline — my file, not the send site), but flagging it here so Archi/integration explicitly decides whether the 00:05 tick's `channel.send(...)` call should honor `reminders.in_dnd_now` the way every other proactive send in this codebase does, or whether grace intentionally bypasses it (arguably defensible: 00:05 is already a quiet hour for nearly everyone, and the message reports something that already happened, not a nag).
- **`format_grace_message` joins multiple same-night bridges with `"\n\n"`** (a blank line between habits) — not specified verbatim by the spec's single-habit sample copy; a reasonable, easily-revised choice if Vera or Archi want a different multi-habit shape (e.g. one shared header, mirroring `core/nudge.py:build_nudge_message`'s header+lines shape instead of N full standalone sentences).
- **`grace_status_line` renders `""` when `[grace] enabled=false`**, on the reading that AC17's "byte-identical to a graceless world" extends to the `/habits` display, not just the bridging mechanism — the alternative (always show "available", since it can genuinely never be spent) was rejected as misleading. Integration's `/habits` renderer must treat an empty string as "omit this line" (mirrors `core/nudge.py:build_nudge_message`'s own falsy-means-skip contract).
- One unrelated, pre-existing failure noted above (`test_reserved_trigger_words_covers_every_real_command_stem`, module `wrapped`'s own territory) — not investigated further per scope; flagged to Archi.
