## Adversarial verification performed (beyond Luna's own 38 tests)

1. **Routing precedence, structurally confirmed.** Read `core/commands.py:dispatch` directly (lines 482–529): the checked order is `undo → edit → snooze → target → help → habits → query → None`, matching R-D1's required "`... → target → help/habits → query → extractor`" precedence exactly. Verified `/target help` resolves as a `target`/`show` command naming the (unrecognized) habit "help" — proving `_match_target` runs and returns before `_match_help` is ever reached, so a target command can never be shadowed by the help matcher. Confirmed `_HELP_RE`/`_HABITS_RE` require the **whole stripped message** to equal one of the five literal strings (`^(?:/help|ช่วยเหลือ|วิธีใช้)$` / `^(?:/habits|นิสัย)$`), so `"I need help drinking more water"`, `"logging my habits: 500ml water today"`, and every Thai mid-sentence case in Luna's own corpus correctly fall through to `None`. One benign, spec-compliant edge case documented (not a defect): `/help?` doesn't match `_HELP_RE` (extra character) and instead satisfies the pre-existing v0.8 trailing-`?` query anchor — the user still gets a safe, helpful reply via the query answerer, just not the literal `/help` formatter; flagged as a test so this boundary can't silently drift without a spec citation.
2. **Ollama-down / LLM-raising, exercised through the real `main.py` wiring** (mirroring `tests/test_v11_integration.py`'s own pattern — `handle_inbound_message` end to end, real `commands.dispatch`, real routing, never a mocked dispatch call). Beyond Luna's existing "Ollama down + `_NeverCalledLLM`" coverage, this pass added the inverse and stronger cases: `health_monitor.ollama_up = True` **plus** an LLM that raises `RuntimeError` on any call — proving `/help`/`/habits` are unconditionally LLM-free, not merely "happen to be skipped because Ollama looked down"; `health_monitor=None` (unwired, e.g. `--dry-run`/CLI paths); and a direct proof that `/help` never falls through to the deferral branch under Ollama-down (`logs` table stays empty, reply is not `deferred_ack`) — this closes the loop on "routing truly sits before the deferral check" with an assertion on the deferral branch's own observable side effects, not just on the correct reply text.
3. **`/habits` correctness**, per the coordinator's four bullets: (a) DB target override → "your target" with the override value, **via the real `/target water 1800` command** (not `db.set_target` called directly) — closing the gap between "the formatter reads `db.get_target` correctly" (Luna's existing coverage) and "the whole `/target` → `/habits` user-visible round trip works"; (b) `/target water default` afterward → the overview flips back to "default" with the correct restored value (2500), again through the real command; (c) a standalone goal-less-habit ("no goal") check isolated from the override scenario; (d) an exact-second Asia/Bangkok-style day-boundary test — a log at `23:59:59` is excluded once the query clock crosses into the next day and included while the clock is still the same day, and a log at `00:00:01` is correctly attributed to its own (new) day — confirming the `ts LIKE '<day>%'` prefix-matching mechanism (shared with every other day-boundary consumer in the codebase) has no off-by-one at either edge; (e) all four aggregation functions (`sum_value` for numeric and duration, `count_true` for boolean with a falsy entry correctly excluded, `count` for text) exercised together in a single `/habits` call against a 4-kind registry, confirming no cross-habit interference.
4. **`/help` tracks config**, beyond Luna's single weekly-review-time A/B test: milestones list changes end to end with no cross-contamination between two different configured lists, and multiple quiet-hour windows all render (not just the first).
5. **i18n integrity.** Rendered `build_help_text`/`build_habits_overview` in both `en` and `th` against a fully-populated config and asserted no exception (a missing/mismatched `{kwarg}` in a catalog template raises `KeyError` immediately — this is a real, load-bearing check, not a tautology) and no `�` (Unicode replacement character, the standard mojibake tell). Confirmed EN and TH outputs are genuinely different strings for both formatters (not a copy-paste placeholder). Tightened Luna's menu-registration subset check (`{"undo","target","help","habits"} <= set(names)`) to an **exact**-set + no-duplicates check per language, closing the gap where an accidental fifth/duplicate entry could creep into the merge undetected.
6. **Bonus regression: full combined adversarial corpus.** Ran `test_commands.py`'s original 10-message AC5.5 corpus together with this module's own 8-message corpus (18 total, including the coordinator's two literal examples) through `commands.dispatch` and asserted none resolves to an **action-taking** command kind (`undo`/`edit`/`snooze`/`target`/`help`/`habits`). One message (`"ขอความช่วยเหลือหน่อยได้ไหม"`, "could I get some help please?") does dispatch as `"query"` — this is pre-existing, correctly-scoped v0.8 behavior (it ends in the Thai interrogative marker "ไหม", one of `_QUERY_PATTERNS`'s five anchors, unrelated to and unmodified by the discoverability module) and is safe by construction: it routes to the read-only query answerer, never mislogs or silently swallows anything. Documented explicitly rather than silently excluded, so the reviewer can see exactly why it's not a `help`/`habits`/action-command false positive.
